## What this repo is

The **CipherTrust Terraform Provider** lets users manage Thales CipherTrust Manager (CM)
resources using Infrastructure-as-Code. It translates `terraform plan/apply/destroy` calls
into CipherTrust Manager REST API calls. It is published at
`github.com/ThalesGroup/terraform-provider-ciphertrust` on branch `1.0.1`.

CipherTrust Manager (CM) is Thales's enterprise key-management platform. Provider
sub-areas: **CM** (core platform), **CCKM** (cloud key-management — AWS/Azure/GCP/OCI),
**CTE** (CipherTrust Transparent Encryption — file/volume encryption policies).

```

  <service>/           # e.g. cckm/aws/, cm/, cte/
    resource_<name>.go    # CRUD logic — Create/Read/Update/Delete

examples/              # hand-written HCL usage examples
```

The provider uses the **Terraform Plugin Framework** (not SDKv2). All new resources must
use `resource.Resource` / `datasource.DataSource` interfaces from
`github.com/hashicorp/terraform-plugin-framework`.

## ⚠ Critical project constraint — TFIN-174

**Empty `Read()` is the root cause of ALL drift issues.** Every resource's `Read` method
currently returns without calling the CM API, so Terraform never reconciles state against
reality. This masks all other bugs (immutable-field violations, case mismatches, tag swaps).

**Fix order is mandatory:**
1. Fix `Read()` first (TFIN-174) — once API is called during plan, all drift becomes visible.
2. Fix `RequiresReplace` on immutable fields (TFIN-183, TFIN-179, TFIN-181).
3. Fix case normalization and JSON tag issues (TFIN-195, TFIN-194).

If your task is NOT TFIN-174, do not implement a proper `Read()` as a side-effect — it will
surface drift before the immutable-field fixes are in and will confuse users. Leave `Read()`
empty unless the ticket specifically asks you to fix it.

## Files to Modify

### 1. `internal/provider/cm/resource_user.go` (primary change)

Replace the empty `Read(ctx, req, resp)` body on the `resourceCMUser` struct. The state model type is **`CMUserModelTFSDK`** (confirm exact name in this file's existing `Create`/`Update`; if it is `CMUserTFSDK`, use that — both names appear in this package's convention). Implementation steps:

- Call `req.State.Get(ctx, &state)`; append diagnostics; early-return on error.
- Extract `state.ID.ValueString()` as the user UUID.
- Call the CM client read method. Per existing usage in `Create`/`Update` of this same file, the method is **`r.client.GetById(ctx, id, common.URL_USER_MANAGEMENT)`** returning `(string, error)` where the string is the raw JSON body. (This matches the generic `GetById` helper in `internal/client/client.go` used by other CM resources.)
- 404 detection: the `GetById` helper returns errors whose message contains `"resource not found"` — match the pattern used in `internal/provider/connections/resource_scp_connection.go`'s `Read()`, which compares via `strings.Contains(err.Error(), "resource not found")`. On match, call `resp.State.RemoveResource(ctx)` and return. On other errors, append an error diagnostic and return.
- `json.Unmarshal` the response into a `CMUserJSON` response struct (already defined in this file for `Create`/`Update`).
- Map every attribute currently declared in the user schema in `internal/provider/cm/schema_cm.go` under `CMUserSchema`. The complete set is: `id`, `user_id`, `username`, `email`, `name`, `nickname`, `password`, `password_change_required`, `password_policy`, `user_metadata`, `failed_logins_count`, `failed_logins_initial_attempt_at`, `last_failed_login_at`, `last_login`, `logins_count`, `password_changed_at`, `enable_cert_auth`, `certificate_subject_dn`, `connection`, `app_metadata`, `allowed_auth_methods`, `allowed_client_types`, `prevent_ui_login`. If the in-tree schema declares fewer/more, conform to that file — do not invent attributes.
- **Write-only preservation**: after inspecting the schema, `password` is the only write-only secret. Copy `state.Password` into the new model before `Set` rather than reading from the API response (the API never returns it).
- `resp.State.Set(ctx, &newState)`; append diagnostics.
